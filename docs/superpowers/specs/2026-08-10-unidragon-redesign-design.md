# Unidragon store redesign — design spec

Date: 2026-08-10
Status: approved
Repo: `Greenfield-Taster/woodtrick` (private)

## 1. Purpose

A design-only demo that shows the client what their store could look like. No backend,
no payments, no CMS. Everything the page needs is static data shipped with the bundle.
The deliverable is judged on craft: how it looks, how it moves, how it reads.

Reference site being replaced: `unidragon.us` (wooden laser-cut jigsaw puzzles).
The client also owns `woodtrick.com` (mechanical model kits); this demo targets the
Unidragon line. Markets: US and EU.

### Non-goals

- No real cart persistence, checkout, auth, or inventory.
- No CMS integration. Product data is a typed TS module.
- No SSR. Client-rendered SPA served by the Aspire-hosted server.

### Legal constraint

No asset from `unidragon.us` is copied — no photography, no logo files, no product
copy. All imagery is generated by us or sourced under CC0/Unsplash-License and
processed. Marketing copy is written fresh. Product names, prices and size tiers are
factual catalogue data and are restated in our own words.

## 2. Positioning

The current site reads as a generic storefront: discount banner, uniform card grid,
loud badges. Premium competitors (Nervous System, Artifact) win with gallery-like
restraint instead.

Direction: **wood is the hero material.** Not "a puzzle shop" but "a workshop that
cuts wood with a laser." Tactility, weight, grain, shadow.

The product truth we build everything around, and which the current site underuses:
**no two pieces are alike, and the reverse side carries a hidden illustration.**

## 3. Visual language

### Palette

Dark base; wood is the only product colour; exactly one accent.

| Token | Value | Role |
|---|---|---|
| `--ink` | `#14100C` | page background, warm near-black |
| `--ink-soft` | `#221B15` | cards, raised surfaces |
| `--paper` | `#F3ECE1` | light sections, text on dark |
| `--birch` | `#E0C398` | light plywood |
| `--walnut` | `#7A4E28` | walnut, depth |
| `--ember` | `#D8602C` | sole accent: CTA, price, focus ring |
| `--moss` | `#5A6B4C` | secondary, "nature" collections |

Sale prices are `--ember` text, never a red badge.

### Typography

- Display: `Fraunces` variable (`SOFT` and `WONK` axes give a handmade feel).
- UI: `Inter Tight`.
- Both self-hosted via `@fontsource-variable`. No external font CDN — the CSP-free
  local build must work offline.
- Headings use `text-wrap: balance` and generous tracking.

### Layout

Asymmetric 12-column grid with deliberate breaks: a product image may overrun its
column, a caption may sit vertically in the gutter. This is what removes the
template feel.

## 4. Hero — self-playing, no scroll required, ~2.6 s

1. Dark stage, warm rim light, silence.
2. ~180 wooden pieces fly in from a dispersed cloud. Real whimsy-cut outlines,
   generated procedurally (bezier tabs and blanks, extruded), PBR wood material.
3. They settle into the wordmark `UNIDRAGON`. Target positions come from sampling the
   wordmark rendered to an offscreen 2D canvas, so the lettering is exact at any
   viewport width. Stagger by travel distance; spring easing with slight overshoot.
4. On settle, a light sweep runs across the grain (shader uniform), then the
   subheading and CTA rise into place.
5. Idle: subtle breathing plus damped mouse parallax. Every few seconds one piece
   flips to reveal the hidden reverse illustration — teasing the product truth.

### Implementation notes

- `InstancedMesh`, a handful of geometry variants, per-instance matrix and colour.
- Spring integration inside `useFrame`. GSAP drives DOM only, never per-instance
  transforms.
- `prefers-reduced-motion` renders the assembled wordmark immediately, no flight.
- Mobile tier: 60 pieces, no shadows, `dpr` capped at 1.5.

## 5. Home page structure

Three WebGL surfaces on the whole site. Everything else is CSS/SVG. That is the
balance between spectacle and information.

| # | Section | Motion |
|---|---|---|
| 1 | Hero | 3D, self-playing |
| 2 | Three reasons | one piece, rotation bound to scroll |
| 3 | Collections | six cards, grain reveal on hover (CSS) |
| 4 | Bestsellers | horizontal rail, real prices |
| 5 | Size comparison S→King | interactive, SVG, with a scale reference |
| 6 | The hidden side | 3D, piece flips on scroll |
| 7 | Trust | free shipping over $49.99, gift box, reviews |

## 6. Other routes

- **PDP** — 3D configurator: switch size S/M/L/King (piece count and footprint change
  live), orbit, flip to the reverse side, choose plywood tone. Alongside: price,
  assembly time, piece count.
- **Catalog** — filters (collection / size / price), asymmetric grid, instant
  client-side filtering.
- **Cart** — side drawer, free-shipping progress bar, USD/EUR toggle for the two
  target markets.

## 7. Assets

The client supplies nothing, so every asset is ours.

- **Piece outlines** — generated in code.
- **Mandala / geometric / pop-art artwork** — generated procedurally.
- **Nature and animal artwork** — CC0 imagery run through a posterise/duotone shader
  so it reads as designed print, not photography.
- **Product imagery for cards** — baked by us. A hidden `/bake` route renders each
  product in 3D; Playwright walks it and saves PNGs into `public/products/`. This
  gives perfectly consistent own-brand product shots and keeps the catalogue from
  mounting 24 live canvases.

## 8. Stack

React 19 · Vite 7 · TypeScript · React Router 7 · Tailwind v4 · zustand (cart) ·
`three` + `@react-three/fiber` v9 + `@react-three/drei` · GSAP ScrollTrigger (DOM only).

R3F v9 is the correct pairing for React 19. Every three.js API is confirmed against
context7 before use, never written from memory.

### Quality tiers

`desktop` / `mobile` / `reduced-motion`, resolved once and passed through context.
Tier controls piece count, shadow maps, `dpr`, and whether idle animation runs.

### Discipline

- Dispose geometries, materials and textures on unmount.
- Measure draw calls and texture memory with the `threejs-devtools` MCP server before
  optimising.

## 9. Project structure

```
frontend/
  frontend.esproj          # recreated so WebStarter.sln and Aspire build
  src/
    app/                   # router, layout, providers
    routes/                # Home, Catalog, Product
    components/ui/         # Button, Price, Badge, Rail, ...
    components/sections/   # Hero, Reasons, Collections, Sizes, HiddenSide, Trust
    three/
      hero/                # HeroScene, PieceField, useWordmarkPoints
      piece/               # outline generation, wood material
      shared/              # lighting rig, quality tier hook
    data/                  # products.ts, collections.ts
    store/                 # cart (zustand)
    styles/                # tokens.css, index.css
```

`WebStarter.AppHost` already wires the app via `AddViteApp("webfrontend", "../frontend")`;
`frontend.esproj` must exist for the solution to load.

## 10. Verification

It is a design demo, so testing is deliberately light:

- Playwright smoke run: each route mounts, hero canvas reports a non-zero draw call
  count, no console errors.
- Manual check at 390 px, 768 px and 1440 px.
- `prefers-reduced-motion` path checked explicitly.
